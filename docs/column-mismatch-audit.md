# API ↔ Schema column-mismatch audit

Generated by a static auditor that cross-references every `.from(table).select(...)`
in `apps/api/src` against the **authoritative schema** (all migrations applied to a
local Postgres, then introspected via information_schema). A flagged column is one the
code selects that does not exist on the table → PostgREST rejects it → the query errors
(hard **500** if the handler checks `error`, otherwise silent **null/empty** degradation).

**127 mismatches across 37 tables.** Fix-types vary:
- **Rename** — column exists under a different name (e.g. `severity`→`conflict_severity`).
- **Structural** — column was moved to another table (e.g. `employees.department_id` → `employee_org_assignments`); needs a join, not a rename.
- **Missing table** — tracked separately in the unbuilt-tables work.

## Already fixed (verified, shipped)
- `attendance_policy_conflict_log`: `severity/resolution/note/updated_at` → `conflict_severity/resolution_source/conflict_explanation/created_at` (routes/attendance/policy-conflicts.ts) — was a live 500.
- `holidays` → `holiday_calendar` (lib/roster-calendar-engine.ts, lib/work-session-engine.ts).
- `governance_events` → `governance_drift_events` + `created_at`→`detected_at` (routes/executive/index.ts).
